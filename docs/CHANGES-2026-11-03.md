# Code review remediation, 3 Nov 2026

All 27 findings from the 3 Nov 2026 review are fixed, each with a regression test that fails on the previous code.
Design decisions are recorded in [ADR-0001](adr/0001-scheduler-and-event-delivery.md) (scheduler and event delivery)
and [ADR-0002](adr/0002-django-5-2-lts.md) (Django 5.2 LTS).

## Upgrade notes

- Run `manage.py migrate`: new tables `core.SchedulerLease`, `core.JobState`, `servicedesk.IncidentKey`, `administration.LoginThrottle`.
- Django is now 5.2 LTS (`requirements.txt`). The apps still run on 4.2 for LinkedEyeWebProject.
- New settings (all optional; see DEPLOYMENT.md): `LINKEDEYE_EMAIL_TIMEOUT`, `LINKEDEYE_NOTIFY_ASYNC`, notification digest and pool sizes, scheduler heartbeat and pass budget, `LINKEDEYE_LOGIN_MAX_FAILURES`, `_PER_IP`, `_WINDOW_MINUTES`.
- A second `run_probes` now idles instead of double-running checks, so a stray replica or an overlapping cron `--once` is harmless.
- Permission rule change: records for **All Sites** need the role on every site to be *changed* (tickets, SLA policies, catalog, BOD/EOD modes, holidays, domains, URL checks, report schedules). Operators of any one site can still *run* checks on them.
- The dashboard is now the Operations overview: market-day strip (IST), per-site health matrix, attention queue and event stream.
