How it works

  1. The file is read and checked. You see how many rows each sheet would create, change or retire.
  2. Confirming writes the rows. An import is idempotent: importing the same workbook again changes nothing.
  3. A row the new snapshot no longer contains is marked “no longer present” — never deleted, never silently kept as current.

At most {{ max_mb }} MB. Accepted: the .xlsx workbook, or a .zip of its sheets exported as CSV (same file names as the sheets).

What is stored

The discovery is read-only and never reads a Secret's contents. This module stores Kubernetes Secret names and namespaces only — there is no field anywhere in it that could hold a secret value.

Cells the collector could not fill (“NOT DISCOVERED”, “NOT APPLICABLE”, “MANUAL INPUT REQUIRED”) mean no value: they are stored as empty and shown as a dash, never as data.

The sheet-by-sheet format and the kubectl commands that produce it are in docs/IMPORT.md.
