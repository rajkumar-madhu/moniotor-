Troubleshooting
  1. Is the shipper running? On Linux: systemctl status vector and journalctl -u vector -n 50. Run vector validate /etc/vector/vector.toml to check the file.
  2. Did you paste the file the page generated, with the token in it? A 401 in the Vector log means the token is wrong or was rotated since: generate the configuration again.
  3. A 503 means log ingest is switched off on the server (no LINKEDEYE_LOG_INGEST_TOKEN).
  4. Can the host reach {{ ing.url }}? Check outbound HTTPS from the host and that its firewall or proxy allows it: curl -sS -o /dev/null -w "%{http_code}" -X POST {{ ing.url }} should answer 401 (reachable, no token), not time out.
  5. The shipper reads new lines only (it starts at the end of each file). Generate some: logger "linkedeye test", then wait a few seconds.
  6. Files must be readable by the Vector user (for example the adm group for /var/log/syslog), and the host clock should be close to the console's.
    7. {% if t.target_type == "device" %}
  7. The device must send syslog to the collector running Vector (UDP 514) and the collector must allow it through its firewall.
    8. {% endif %} {% if t.target_type == "k8s_node" %}
  8. Run Vector as a DaemonSet with the node's /var/log mounted read-only and a service account that can list pods.
    9. {% endif %}
